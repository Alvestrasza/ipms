# Native console input and liveness: 0.2.41

Status: **implemented; owner-authorized publication and DEV activation pending**.

## Findings and acceptance boundary

The operator reported another disconnect after the 0.2.40 deployment. Read-only
inspection confirmed the current broker source, a renderer input timeout and
an unexpired session lease. No service restart explained the disconnect. Those
observations alone do not identify which browser event preceded the failure.

An actual-browser regression with the pinned renderer reproduced a separate,
deterministic input defect: the component passed boolean key states through a
length-prefixed string serializer, producing `true`/`false` instead of `1`/`0`.
The broker correctly rejects that invalid input. The test failed before the fix
with the actual emitted key instructions, not a mocked client implementation.

The old browser integration test exercised mouse input only after a click and
accepted any key instruction prefix. The new test asserts hover movement and
focus before a click, exact numeric key states, streamed PNG decoding, rendering
acknowledgment, mouse buttons/wheel, secure attention and a genuine idle period.
Hover movement alone already reached the synthetic transport before the change;
real guest cursor behavior remains a separate acceptance check.

## Changes

- Send numeric pressed/released values and use a `0 | 1` TypeScript contract.
  Keep the broker's strict validation rather than accepting malformed input.
- Focus the console on mouse entry without an initial click. Clamp coordinates
  to the scaled display bounds, and release held keys/buttons on blur or close.
- When application messages stop, send a native WebSocket ping and await its
  actual matching pong. Revalidate authorization before forwarding a renderer
  `nop`. This removes the renderer's dependence on page-level heartbeat timers.
  Missing pongs terminate the connection; no synthetic sync acknowledgment,
  guest input or authorization-lease extension is generated by this path.
- Remove the additional acknowledgement checkbox and certificate dialog.
  Opening a session still requires an owner, permission, a configured service
  account, a supported Agent and the exclusive VM session lease.

## Certificate behavior

The owner explicitly requested removal of both per-session confirmations.
The browser now automatically binds the connection to the validated certificate
observation provided through the authenticated Agent's fixed local endpoint.
The renderer still accepts exactly that leaf with a valid time window, and a
change between observation and connection fails closed. TLS, Agent mTLS, tenant
isolation, Origin/session checks and redirect rejection are unchanged.

This is **per-connection observed-certificate binding**, not CA validation or a
persistent cross-session host pin. A new valid certificate may be observed on
the next session without prompting the operator. Audit events use
`certificate.bind`, not `certificate.accept`: no manual certificate approval or
checkbox acknowledgement is fabricated. No certificate is saved in browser
storage, and no new database schema or broker privilege is required.

## Verification

- The input regression failed against the preceding browser code and passed
  after the numeric-state correction.
- A real WebSocket/TCP relay regression without JavaScript/application pings
  failed before the native-PONG path and passed afterward for approximately
  40 seconds, beyond the renderer timeout and initial session lease.
- A peer that suppresses native PONGs closes within the bounded deadline without
  any fabricated renderer input. Existing revoked-access cleanup also passes.
- All five native browser scenarios passed against the production build,
  including real PNG decoding and 45 genuine browser heartbeat intervals.
  Only native configuration/session/transport endpoints are simulated; fixture
  login and SSR inventory are real. No Agent or hypervisor is contacted.
- Fourteen Node tests passed, including the pinned artifact/SRI/license checks.
- All **73 focused backend tests passed on Linux/Python 3.14 with PostgreSQL**,
  without skips, against a checksum-verified isolated source archive. The test
  database was removed afterward and the active 0.2.40 release remained intact.
- The production build, TypeScript and targeted Biome checks passed. Migration
  drift check: no changes. Local fixture processes and browser sessions were
  stopped, and their listening ports were released after browser acceptance.

The browser-driver wrapper could not initialize a usable session with the local
Edge/test-browser setup. Browser acceptance used the existing Playwright harness
and bundled test Chromium instead; no browser sandbox policy was weakened.
React review confirmed one scoped input subscription, transient input outside
React state, cleanup of listeners/timers and no input replay or automatic
transport fallback.

## Deployment and remaining work

Use `scripts/deploy-console-input-dev.sh` from the verified 0.2.40 DEV baseline.
The schema-neutral cutover preserves environment and network policy, refuses
active work, stages before switching and retains the previous immutable release
and protected recovery material. No installed Agent or guest configuration
change is part of this release.

Bash syntax validation and the exact-target, non-mutating deployment preflight
passed against DEV. The owner subsequently authorized publication to `main` and
activation on the existing DEV appliance. A fresh preflight reconfirmed the
expected source/runtime baseline and no active work before publication.

The candidate is not yet published or activated. Real-host acceptance must still
cover opening without prompts, idle/focused/background windows, mouse movement,
typing and close/reopen. Do not equate isolated tests with a confirmed resolution
of the operator's remaining timeout.
